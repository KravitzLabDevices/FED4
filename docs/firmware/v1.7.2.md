# Firmware v1.7.2

Published library on board **v1.7.0**. Arduino-ESP32 core stays **3.2.1**.

PIR activity comes from the **S-35770E01** event counter (I2C `0x32`). The library never resets that chip. `begin()` stores the count it finds and only uses later differences, so a large leftover count does not matter and a reset is not required.

## Activity%

The EKMB1107112 can emit more than one rising edge during its ~2.6 s standby hold, and that hold length changes with how many of those edges occur. Counting every edge as its own detection overstates activity.

Each gap between counter reads is scored once:

```text
credit = 0                              if the gap has no new edges
credit = min(gap, pirHoldSeconds)       if the gap has one or more edges
Activity% = sum(credit) / window × 100
```

`pirHoldSeconds` defaults to **2.6**. The 1.3 s mask is time the sensor is blind, so it is not counted. Ten edges in one gap score the same as one edge. 100% means every moment of the window is inside a detection hold.

Two separate visits inside one unread gap still count as a single hold. Separating them means reading the counter more often, not a different formula.

GPIO 10 (`PIR_MOTION`) is unchanged: input pulldown, and `STATUS_LED` still mirrors the live level. It is not a wake source.

## Two windows

| Surface | Period |
| --- | --- |
| Serial, activity screen, touch-log `Motion` | Rolling window, `activityWindowSeconds` (default 300 s). `millis()` keeps running through light sleep. |
| Behavioral CSV `Activity` | Since the previous row. Any edges in that gap credit one hold. Use the rolling value for trends. |

The rolling window keeps 16 samples and only stores a new one after `window / 16`. Poke wakes do not flush it. Each stored step is scored on its own, so extra edges inside one step do not add. Before the window has filled, the value uses the time since the oldest sample.

If the addon is missing, boot continues and `Activity` says `NoCounter`. If `useMotionSensor` is false, it says `Disabled`.

## CSV

Behavioral log, after `MotorTurns`: one column, `Activity` (percent, one decimal). This replaces the old `Motion` percentage column from v1.7.1. v1.7.1 files do not have this counter-based value.

The touch log keeps the column name `Motion` and stores the rolling activity percent.
