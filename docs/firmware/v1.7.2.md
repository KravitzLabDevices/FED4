# Firmware v1.7.2

Published library on board **v1.7.0**. Arduino-ESP32 core stays **3.2.1**.

PIR activity comes from the **S-35770E01** event counter (I2C `0x32`). The library never resets that chip. `begin()` stores the count it finds and only uses later differences, so a large leftover count does not matter and a reset is not required.

## Activity

The EKMB1107112 can emit more than one rising edge during its ~2.6 s standby hold. Counting every edge as its own detection overstates activity.

The counter is read about every 4 s (`PIR_SAMPLE_MS`), including brief wakes during light sleep. An 80-slot ring covers a 300 s window. Each gap is scored once:

```text
credit = 0                              if the gap has no new edges
credit = min(gap, pirHoldSeconds)       if the gap has one or more edges
```

`pirHoldSeconds` defaults to **2.6**. The 1.3 s mask is time the sensor is blind, so it is not credit and it is not removed from the window. Extra edges in one gap do not add. Two separate visits inside one unread gap still count as a single hold.

A full hold in every 4 s gap is `2.6 / 4` (about **0.65**). The logged and displayed value is scaled so that ceiling is **1.00** (display and Serial show that as 100%). Activity stays blank until the scored span is at least one 4 s gap.

`begin()` copies a non-zero `vitalIntervalSeconds` into `activityWindowSeconds`, so the rolling window matches the Vital period (default 300 s). `millis()` keeps running through light sleep.

| Surface | What it shows |
| --- | --- |
| Serial, activity screen, touch-log `Motion` | Rolling window, 0–100 |
| Behavioral CSV `Activity` | Same window, Vital rows only, **0.00–1.00**. Event rows leave the cell blank |

## Vital rows

The behavioral CSV is still event-based, plus one time-based event named `Vital`.

Set the period from the sketch before `begin()`:

```cpp
fed4.vitalIntervalSeconds = 300; // seconds; 0 disables Vital rows
fed4.logGasPressure = true;      // optional column group
fed4.begin("BasicFED4");
```

`millis()` keeps running through light sleep, and that clock decides when the row is due. `begin()` arms the timer after the `Startup` row, so boot does not also write a Vital. `update()` writes the row when it is due, including the fast poke path, so a stretch of pokes cannot skip it. `logVital()` forces one row and restarts the interval.

`startSleep()` shortens its light-sleep timer when the next Vital is sooner than the sketch's wake interval. That wake returns as `FedWakeSource::Timer`, which task sketches already ignore.

Optional groups stay in the header and are left blank when off, so concatenated logs keep those columns.

Always written, on every row: Temperature, Humidity, Lux, WakeCount, BatteryVoltage, BatteryPercent, plus the existing counters.

| Sketch flag | Default | Columns |
| --- | --- | --- |
| `logHeap` | off | FreeHeap, HeapSize, MinFreeHeap |
| `logGasPressure` | off | Pressure on every row. GasResistance on Vital rows only |
| `logWhite` | off | White (VEML7700 raw) |

Activity is written on Vital rows only, the same cadence as GasResistance, so a plot has one point per interval. RetrievalTime, PokeDuration, DispenseError, and MotorTurns are blank on that row. Counters are the running totals.

Flags default off. A sketch that does not set them leaves Pressure, GasResistance, White, and the heap cells empty.

## Gas heater

`bme.begin()` turns the heater on (320°C for 150 ms, about 10–15 mA). The library turns it off again after init. Routine temperature, humidity, pressure, and light reads do not power the heater. `logVital()` heats for one reading when `logGasPressure` is on, then turns the heater off. `getGasResistance()` does the same for a direct read. A failed gas read leaves the cell blank. `getAllBME680Data()` reports gas as 0 while the heater is off.

`setGasHeater(0, 0)` disables the element but leaves the last on-time in a private Adafruit field, so `performReading()` still waits out that 150 ms. The wait does not mean the heater is drawing current.
